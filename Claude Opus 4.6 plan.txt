PNK Astro Bot — Professional RAG Architecture Plan
Current Problems
CHUNK_SIZE=180 — way too small, fragments context mid-sentence
No PDF ingestion — 8+ PDFs in docs/ are ignored
No hybrid search — semantic-only misses exact terms (planet names, Tamil keywords)
Two languages (Python ingestion + Node.js bot) — unnecessary complexity
No re-ranking — top-8 chunks may include irrelevant noise
In-memory chat history — lost on restart
No structured data handling — numerology JSON chunked as raw text
Architecture Plan (7 Steps)
Step 1: Consolidate to Python — Rewrite pnkastro_bot.js as bot.py using FastAPI + python-telegram-bot. Single language = simpler deployment on 2CPU/4GB VPS.

Step 2: Fix chunking pipeline in update_chromadb.py:

CHUNK_SIZE → 512, CHUNK_OVERLAP → 64
Add PDF loader (PyMuPDF / pymupdf4llm) for the 8+ Tamil/English PDFs
Add JSON loader for numerology_*.json — convert each entry to a natural-language sentence before chunking
Switch embedding model to nomic-embed-text:latest (768-dim, faster, better for retrieval than paraphrase-multilingual)
Use paraphrase-multilingual:latest only for query embedding (cross-lingual Tamil↔English)
Step 3: Hybrid retrieval — Add BM25 keyword search alongside vector search:

Store BM25 index using rank_bm25 (pure Python, no extra server)
At query time: get top-10 from vector + top-10 from BM25 → merge with Reciprocal Rank Fusion (RRF)
This fixes exact-match failures for planet names, Tamil terms, numbers
Step 4: Re-ranking — After RRF merge, use paraphrase-multilingual to compute cosine similarity between query and each candidate chunk. Keep top-5. This is cheap (just embedding comparisons).

Step 5: Structured query routing — Detect query intent before retrieval:

Numerology query (contains digits) → filter source_type=numerology + do exact JSON lookup
Company/pricing query → filter source_type=company_detail
General astrology → no filter, full hybrid search
Keep your existing TOPICS map but expand it
Step 6: Persistent chat memory — Replace in-memory Map with SQLite (sqlite3 stdlib). Table: (session_id, role, content, timestamp). Load last 6 messages per session. Auto-prune after 24h.

Step 7: Production deployment on VPS:

systemd services: chromadb.service, pnkastro-bot.service
Nginx reverse proxy with rate limiting for /chat endpoint
Health check cron job every 5 min
Log rotation with journald
